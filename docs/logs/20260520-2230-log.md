### PR-03 — download cancellation semantics (commit `38cde2a`)

- `CANCEL_EVENTS[job.id] = threading.Event()` per download job.

## Lessons recorded in the ledger

- Three rounds of PR-02 adversarial review missed PR-02-D10 because every
  test patched the executor payload. A correction note is appended to
  PR-02's Completed entry. Tests must exercise production paths, not
  hand-crafted equivalents, when validating contextvar / threading
  behaviour.
- HF's `snapshot_download` produces exactly one byte-unit `ProgressTqdm`
  close per snapshot (the aggregate `bytes_progress`); per-file byte bars
  go through `_AggregatedTqdm` which does not enter our patched class.
  PR-04's initial "every close = one file" comment was factually wrong.
  Documented in PR-04's Completed entry.
- `loop.run_in_executor` does NOT propagate contextvars in CPython 3.13.
  Callers MUST `ctx = contextvars.copy_context()` and dispatch via
  `lambda: ctx.run(func, *args)`. Documented in
  `src/zimt/webui/downloads.py`'s module docstring and in PR-02-D10.
